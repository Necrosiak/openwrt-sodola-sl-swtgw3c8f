# Signed firmware updates

## English

The Nekyron theme checks for firmware updates after login without blocking LuCI. A short five-minute cache avoids repeated requests while navigating. **System → Nekyron firmware updates** also provides a manual check, configuration backup download, image download/verification, and an explicit **Install and restart** confirmation. There is no unattended flashing. Settings/passwords are retained using ordinary sysupgrade; extra packages installed outside the firmware may need reinstalling. HTTPS is regenerated after each firmware upgrade, once NTP and DHCP are ready; the browser may require trusting the new public certificate again.

The default channel offers published releases. The optional candidate channel also includes automatically compiled upstream candidates. Candidates are experimental and not hardware validated merely because compilation passed. Each hourly source change is built in a read-only job; signing happens in a separate runner with a repository secret. An immutable OpenWrt usign build signs metadata, and only the public verification key is embedded in firmware. The signing secret is not available to upstream compilation and never shipped in images or artifacts. A successful-publication cache avoids rebuilds when sources have not changed; failed signing/publication remains retryable.

Signed feeds live in the `update-index` release, separately for `full` / `tailscale-lite` and `release` / `candidate`. The updater accepts only this repository's HTTPS URLs and verifies usign/Ed25519 metadata, board ID, exact profile, compatibility contract, increasing build ID, size, RAM budget, SHA-256 and OpenWrt's own `sysupgrade --test`. Installation repeats the signature/hash/platform checks. It never uses `--force`, never factory-resets, and does not accept a caller-supplied download URL or file path. It downloads to RAM and rejects the operation if memory is insufficient. Images with no signed feed are not offered; a full image must never replace the Tailscale lite profile. The installed identity is read from `/rom/etc/nekyron-release.json`, so retained settings cannot make an old identity override the booted image.

A download/compatibility test is not a test of physical flashing. Keep a backup and recovery access. The installer is not executed during development tests. No promise that every CVE is fixed: this follows fixes integrated upstream. Signing proves publisher authenticity and integrity, not bug-free firmware. Public signing fingerprint is available using `usign -F -p package/luci-app-nekyron-update/files/usr/share/nekyron-update/release.pub`.

Maintainers: `scripts/prepare.py` writes the image identity; `scripts/collect.py` collects it. `scripts/sign-update.py` checks that it matches the actual squashfs before signing. `scripts/publish-update.py` publishes the image then its signed feed. CI uses `NEKYRON_UPDATE_SIGNING_KEY`, kept only in the isolated signing job. Reproducible identity timestamps can be set with `NEKYRON_BUILD_EPOCH`. A fork must supply its own signing key, change the repository URLs, and rebuild the verification key into its images.

## Français

À la connexion, le thème Nekyron recherche les mises à jour sans bloquer LuCI ; un cache de cinq minutes évite de répéter les requêtes pendant la navigation. Dans **Système → Mises à jour du firmware Nekyron**, tu peux vérifier manuellement, télécharger une sauvegarde, télécharger/vérifier l’image puis confirmer **Installer et redémarrer**. Aucun flash sans confirmation. Les réglages et mots de passe sont conservés ; les paquets ajoutés manuellement peuvent nécessiter une réinstallation. Après chaque mise à jour, le certificat HTTPS est régénéré après NTP/DHCP : il faudra éventuellement reconnaître le nouveau certificat public dans le navigateur.

Le canal par défaut propose les versions publiées. Le canal optionnel inclut les candidats automatiques expérimentaux. Une compilation réussie ne constitue pas une validation sur matériel. Les sources sont compilées dans un job en lecture seule ; la signature est réalisée sur un autre runner, avec une clé privée stockée dans un secret GitHub. Seule la clé publique est embarquée. La clé privée n’est accessible ni à la compilation amont ni aux images/artefacts publics.

Avant installation : signature usign/Ed25519, modèle exact, profil identique (`full` ou `tailscale-lite`), contrat compatible, version plus récente, taille, RAM, SHA-256 et validation OpenWrt. Les contrôles sont répétés avant le flash. Aucune option de forçage ou de remise à zéro. Une image complète ne sera pas proposée au profil Tailscale léger. Un firmware sans métadonnées signées compatibles n’est pas proposé. Les tests de développement ne déclenchent aucun flash. Les correctifs intégrés en amont sont suivis, sans garantie de corriger toutes les CVE. Les flux signés sont dans la release technique `update-index`.

## Deutsch

Nach der Anmeldung wird im Hintergrund geprüft; fünf Minuten Cache vermeiden Wiederholungen. **System → Nekyron-Firmware-Aktualisierungen** bietet Prüfung, Konfigurationssicherung, Download/Validierung und bestätigte Installation mit Neustart. Kein unbeaufsichtigtes Flashen. Einstellungen/Passwörter bleiben erhalten; zusätzlich installierte Pakete müssen eventuell erneut installiert werden. Nach jedem Firmware-Update wird nach NTP/DHCP ein neues HTTPS-Zertifikat erstellt; der Browser muss diesem gegebenenfalls erneut vertrauen. Standard: veröffentlichte Versionen; automatische experimentelle Kandidaten sind optional. Signatur, Modell, Profil, Vertrag, neuerer Build, RAM, SHA-256 und OpenWrt-Prüfung sind Pflicht. Kein Erzwingen oder Zurücksetzen. Private Signierschlüssel sind nur im isolierten CI-Signierjob verfügbar. Hardwarevalidierung und vollständige CVE-Abdeckung werden nicht garantiert.

## Español

Se comprueban actualizaciones al iniciar sesión, con caché de cinco minutos. **Sistema → Actualizaciones del firmware Nekyron** permite comprobar, guardar la configuración, descargar/verificar e instalar tras confirmar el reinicio. No hay instalación desatendida. Se mantienen ajustes y contraseñas; puede ser necesario reinstalar paquetes añadidos. Tras cada actualización, NTP/DHCP permite regenerar HTTPS; el navegador puede pedir confiar de nuevo en el certificado. Versiones publicadas por defecto; candidatos automáticos experimentales opcionales. Se verifican firma, modelo, perfil, contrato, versión más reciente, RAM, SHA-256 y validación OpenWrt. Sin forzar ni restablecer. La clave privada solo existe en el job aislado de firma. No se garantiza validación de hardware ni corregir todas las CVE.
